# Query Doctor Kubernetes Deployment

Last reviewed: 2026-08-10

These manifests are the supported Kubernetes starting point for running the
Query Doctor web UI from the official container image. They do not add native
authentication, authorization, sessions, RBAC, SQL execution, or multi-tenant
isolation inside Query Doctor, and they do not turn Kubernetes into an
arbitrary command-running surface.

For Helm-based installs, use the chart in `deploy/helm/query-doctor/`. The chart
renders the same public-demo and configured private shapes and adds values
schema, render smoke, Helm NOTES, synthetic self-test smoke, and generic
user-provided pod labels and annotations.

Supported shapes:

- `public-demo.yaml`: read-only synthetic public demo. It starts with
  `query-doctor-web --public-demo`, disables POST actions, needs no credentials,
  and denies pod egress through a `NetworkPolicy`.
- `configured-web.yaml`: private operator deployment template for Impala or
  bounded local Trino workflows. It mounts a Query Doctor config, reads
  credentials from a pre-created Kubernetes Secret, stores generated cases on a
  PVC, mounts the same PVC as a persistent finished-Recent reuse cache, and
  must run behind a trusted ingress or auth proxy for shared access.
- `self-test-job.yaml`: synthetic self-test Job. It runs only
  `query-doctor-self-test --json --timeout-sec 120` without config, credentials,
  PVCs, live engine access, optimizer jobs, metadata collection, or SQL.

The container exposes:

- `/healthz`: liveness probe, raw-free JSON.
- `/readyz`: readiness probe, raw-free JSON.
- `/deployment/readiness.json`: raw-free deployment state summary for operators.
- port `8765`: Query Doctor web UI.

## Image

Release images are published as:

```text
ghcr.io/alexandrefimov/query-doctor:<version>
```

For local builds:

```bash
scripts/build-image.sh query-doctor:dev
scripts/image-smoke.sh query-doctor:dev
```

When building on an arm64 workstation for amd64 Kubernetes nodes, set the
target platform explicitly:

```bash
QUERY_DOCTOR_IMAGE_PLATFORM=linux/amd64 scripts/build-image.sh query-doctor:dev-amd64
QUERY_DOCTOR_IMAGE_PLATFORM=linux/amd64 scripts/image-smoke.sh query-doctor:dev-amd64
```

Check the manifests before applying local edits:

```bash
kubeconform -strict -summary deploy/kubernetes/public-demo.yaml deploy/kubernetes/configured-web.yaml deploy/kubernetes/self-test-job.yaml
```

The image default command runs the safe public demo:

```bash
query-doctor-web --host 0.0.0.0 --port 8765 --allow-nonlocal-web-bind --public-demo
```

The image includes Kerberos client tools and the isolated
`/opt/query-doctor/.venv-impala-shell/bin/impala-shell` executable so
configured private deployments can enable bounded Impala metadata collection
without baking credentials into the image. Metadata collection still requires
an explicit metadata coordinator and a valid Kerberos ticket cache supplied by
the private deployment environment.

The Helm chart adds an optional configured-mode Kerberos initContainer flow for
that cache. It references an existing Secret by name/key only and does not
render Secret objects, keytab contents, ticket contents, or inline credentials.
It also adds optional configured-mode `recentHistory.postgres` wiring that
passes the Recent summary-history Postgres DSN from an existing Secret key into
the web pod environment. When CloudNativePG is already installed, the Helm chart
can also render an optional configured-mode `Cluster` for that backend. Query
Doctor can reference the standard application Secret generated by CNPG through
its `uri` key, or use external owner and DSN Secrets. The chart never renders a
Secret object or accepts inline credentials. The static `configured-web.yaml`
keeps database wiring disabled so the manifest remains directly applicable
without a database Secret or CNPG CRD.
After wiring the Secret-provided DSN env, run
`query-doctor-recent-history-postgres-readiness --json` inside the target
runtime to verify schema initialization with raw-free output.
The same configured image can also run `query-doctor-recent-profile-worker`
with the batch/config flags to process queued Recent profile jobs for the
configured source. It writes only raw-free cache/artifact metadata and does not
run LLM reports, optimizer jobs, metadata SQL collection, or raw profile
storage in the database. The Helm chart can also render an optional
configured-mode `query-doctor-batch-recent --discover-only` CronJob that writes
retained raw-free summary rows and planned profile jobs to Postgres without
collecting profiles, running metadata SQL, LLM reports, or optimizer jobs.

## Public Demo

```bash
kubectl apply -f deploy/kubernetes/public-demo.yaml
kubectl -n query-doctor rollout status deploy/query-doctor-web
```

Expose the `query-doctor-web` Service through your local port-forward, ingress,
or gateway policy. The manifest itself does not configure public internet
exposure.

Check runtime deployment state without exposing config values:

```bash
kubectl -n query-doctor port-forward svc/query-doctor-web 8765:80
curl -fsS http://127.0.0.1:8765/deployment/readiness.json
```

## Configured Private Mode

Create credentials outside git. For Cloudera Manager, provide one of
`CM_PASSWORD` or `CM_TOKEN` plus `CM_USERNAME`:

```bash
kubectl -n query-doctor create secret generic query-doctor-credentials \
  --from-literal=CM_USERNAME='<operator-user>' \
  --from-literal=CM_TOKEN='<read-only-token>'
```

Edit the ConfigMap in `configured-web.yaml` with the target Cloudera Manager or
bounded local Trino config before applying it. Keep source visibility `safe`
unless the deployment has completed the owner-raw D3 front-door review and
support-readiness gates.

The configured web pod is intentionally heavier than the public demo:
`requests.cpu=250m`, `requests.memory=512Mi`, `limits.cpu=2`, and
`limits.memory=2Gi`. Treat this as the minimum baseline for configured Recent
scans and raise it for broader windows, higher parallelism, or larger retained
case sets.

For non-local configured web binds, Query Doctor uses conservative Recent
defaults unless the private config explicitly overrides them: profile analysis
limit `50`, overall Recent parallelism `4`, metadata parallelism `2`, and
metadata top limit `10`. Raise these only with matching pod memory/CPU and a
focused smoke.

The configured manifest also sets `recent_batch_root` to the manifest's
dedicated temp-backed cache mount and backs that mount with the case PVC.
Finished-query Recent scans can then reuse already analyzed safe redacted cases
after pod restart when the Query ID and explicit profile reuse contract match.
Keep custom roots under a dedicated Query Doctor temp-backed path; the web
startup and batch CLI reject unsafe batch roots.

```bash
kubectl apply -f deploy/kubernetes/configured-web.yaml
kubectl -n query-doctor rollout status deploy/query-doctor-web
```

After metadata coordinator settings, the Kerberos ticket cache, and the
configured web release are in place, run the bounded metadata smoke. It checks
the web pod's Kerberos cache and `impala-shell` runtime, submits one Recent
scan through `/batch/run` with `metadata_top_limit=1`, requires collected or
partial metadata with table context, and prints only aggregate status and
table-context counters. The service scan is not published as the latest UI
batch result:

```bash
QUERY_DOCTOR_K8S_METADATA_SMOKE_NAMESPACE=query-doctor \
QUERY_DOCTOR_K8S_METADATA_SMOKE_RELEASE=query-doctor-full \
scripts/kubernetes-configured-metadata-smoke.sh
```

For shared/non-local access, authentication, MFA, sessions, groups, RBAC, TLS,
header stripping, and identity mapping belong to the trusted ingress or auth
proxy. Query Doctor only consumes `viewer_identity_header` after that front
door sets exactly one normalized viewer owner value. See
`docs/owner-raw-d3-deployment.md`.

For configured private deployments that are fronted by oauth2-proxy/Keycloak or
an equivalent platform SSO proxy, use `docs/kubernetes-auth-front-door.md` and
`scripts/kubernetes_auth_front_door_smoke.py` to check the live unauthenticated
redirect chain, then `scripts/audit_kubernetes_auth_front_door.py` to check
that Ingress routes to the auth proxy, the proxy routes upstream to Query
Doctor, secrets are not inlined, token and Basic auth forwarding are disabled,
and deployment readiness remains configured-private, SQL-disabled, and
raw-output-disabled. In strict mode the same audit also checks that
NetworkPolicy allows only the trusted ingress controller to reach the auth
proxy and only the auth proxy to reach the Query Doctor web pods.

For release handoff over an already installed configured release, compose the
metadata, external auth redirect, and static front-door audit gates with:

```bash
QUERY_DOCTOR_K8S_RELEASE_GATE_EXTERNAL_URL=https://<query-doctor-host>/ \
QUERY_DOCTOR_K8S_RELEASE_GATE_EXPECTED_HOST=<query-doctor-host> \
QUERY_DOCTOR_K8S_RELEASE_GATE_EXPECTED_ISSUER_URL=https://<oidc-host>/realms/<realm> \
QUERY_DOCTOR_K8S_RELEASE_GATE_EXPECTED_CLIENT_ID=<oidc-client-id> \
QUERY_DOCTOR_K8S_RELEASE_GATE_INGRESS_CONTROLLER_NAMESPACE_LABELS=<key>=<value> \
QUERY_DOCTOR_K8S_RELEASE_GATE_INGRESS_CONTROLLER_POD_LABELS=<key>=<value>,<key>=<value> \
scripts/kubernetes-configured-release-gate.sh
```

The wrapper prints only component gate names plus raw-free component output.
Keep real URLs, client IDs, labels, retained resource dumps, readiness payloads,
and smoke logs out of committed documentation.

## Synthetic Self-Test Job

Use the self-test Job after applying a pullable image tag when you need a
cluster-side package confidence check without live configuration:

```bash
kubectl -n query-doctor delete job/query-doctor-self-test --ignore-not-found
kubectl apply -f deploy/kubernetes/self-test-job.yaml
kubectl -n query-doctor wait --for=condition=complete job/query-doctor-self-test --timeout=300s
kubectl -n query-doctor logs job/query-doctor-self-test
```

For a disposable Helm-based self-test over a pre-release image, use:

```bash
QUERY_DOCTOR_K8S_SELF_TEST_IMAGE_REPOSITORY=registry.example.com/query-doctor \
QUERY_DOCTOR_K8S_SELF_TEST_IMAGE_TAG=0.11.0-rc \
scripts/kubernetes-self-test-smoke.sh
```

The Job is intentionally narrow. It has no Service, Deployment, Ingress,
ConfigMap, Secret reference, PVC, service-account token, or egress allowance.
Do not repurpose it for Recent scans, Running scans, Known Query ID, optimizer
jobs, metadata collection, Trino/Spark probing, SQL execution, or platform
smoke jobs.

## Boundaries

- Do not expose ordinary local mode without a trusted front door.
- Do not store real config, hostnames, keytabs, tokens, or generated cases in
  git.
- Do not enable `source_visibility=owner_raw` for a shared bind until the D3
  readiness and launch-closure path has passed.
- The manifests run the container as non-root UID/GID `10001:10001`; keep that
  aligned with the Dockerfile when editing security contexts.
- Query Doctor never executes user SQL or optimizer draft SQL.
- Kubernetes support does not change engine support: Impala remains the full
  production triage engine; Trino remains bounded to the documented local
  raw-free lanes.
- The self-test Job is only a synthetic package confidence check, not a live
  diagnostics runner.
