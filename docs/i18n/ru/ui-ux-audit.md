# UI/UX аудит

Last reviewed: 2026-05-26

Язык: [English](../../ui-ux-audit.md) | Русский

Английская версия является канонической. Эта страница - краткое русское
резюме принятых выводов UI/UX аудита.

## Принятый фокус

Details должен быть страницей решения для аналитика, а не витриной
коллекторных внутренних деталей. Видимый путь должен отвечать на вопросы:

- почему этот запрос заслуживает внимания;
- где смотреть в форме запроса, плане, runtime или metadata;
- какое направление изменения попробовать;
- как проверить изменение сопоставимым повторным запуском.

Инженерные diagnostics остаются полезными, но должны быть свернуты или
показаны только там, где они помогают решению, рекомендации, проверке или
явному ограничению.

## Основные направления

- Results table должна быстро помогать выбирать case для разбора.
- Details должен меньше дублировать факты и лучше выделять decision signals.
- Diagnosis form должен сохранять безопасный и понятный путь Recent Scan.
- Кнопки действий должны быть выровнены и читаться как один набор действий.
- Мобильный и desktop layout должны оставаться читаемыми без перекрытий.
